## 1. 现有系统的内部结构

真正的目标是：可靠判断、有效完成、适当交互和尊重个人偏好。检索、澄清、分任务工作流、自检和结论先行是实现手段，不应与目标同级。

现有控制链可以概括为：激活指令→事实判断→选择工作流→补足信息→表达→自检。问题在于“工作流”实际上往往并行发生：翻译含有现实断言，研究服务于决策，排障需要执行，短答可能需要先核验。把这些当互斥模式会导致错误切换。

以下按原文的独立语义规则归组；重复句也在相应位置列入，不据条目数推断效果。

| 原位置/规则组 | 试图解决的具体问题；层级 | 手段、副作用与处置 |
|---|---|---|
| §0 用户级、服从更高优先级 | 正确生效位置；边界 | 保留，不能自行提升权限。 |
| §0 不评价/总结/分析/优化及末尾例外 | 避免把指令当待润色材料；手段 | 四个近义禁止合并成不主动评论，保留明确讨论例外。可能来自过去误触发，但无历史证据。 |

## 2. 失败模式与A/B/C/D归属

A=规则可明显澄清；B=可改善但依赖模型判断；C=主要靠模型、工具或产品；D=未见明显问题，不应继续堆防御。归属针对控制问题，不是保证结果。频率为任务覆盖面推断，没有用户流量数据。

| 问题 | 失败类型与具体触发 | 归属 | 优先级与处置 |
|---|---|---|---|
| F01 当前要求覆盖未限范围 | 优先级不明：这次英语可能污染后续中文；要求作假与诚信竞争 | A | 高；明确局部覆盖及不得伪造。 |
| F02 现实与作品边界 | 规则冲突/任务不兼容：翻译错误句被纠正、虚构被批判 | A | 高；按言语用途划分，不按是否出现错误事实划分。 |
| F03 澄清四条件过严 | 过度约束：礼物对象查不到，但随便选未必“明显错误” | B | 高；允许基于偏好敏感度澄清，保留低风险默认。 |
| F04 新术语一律解释 | 局部规则损害普通高级技术任务；机械遵守 | A | 高；限定必要且可能陌生。 |
| F05 执行等于完成 | 约束不足：写入成功但UI失败 | B | 高；目标相关验证、状态如实报告。 |
| F06 按主题触发检索 | 模糊表达/简单任务复杂化：新闻提取也联网 | A | 中；按关键事实需要核验，保留稳定知识例外。 |
| F07 模式被当成互斥 | 混合任务受损：研究+诗歌、诊断+修复 | A | 中；显式允许组合，删除重复Research。 |
| F08 无检索停止点 | 复杂任务指导不足：反复找源；不必要流程 | B | 中；足够回答就停，证据充分性仍依赖判断。 |
| F09 来源仅形式可靠 | 核验不足：官方月付与年付被当成矛盾 | B | 中；核对条件和引用支持，不强制每题两个来源。 |
| F10 重复指令 | 冗余：反迎合、上下文、篇幅散落多处 | A | 中；合并降低维护时遗漏一处的机会，不能据此承诺性能提升。 |
| F11 待处理资料变成指令 | 信任边界缺位：文章指令污染任务 | B | 高后果、频率未知；补一条边界，真正隔离主要还需产品。 |
| F12 假装记住长对话 | 实际能力不可保证：内容已被截断 | C | 中；声明缺口可约束，恢复丢失上下文不是prompt能做到。 |
| F13 “不解释流程”被过泛化 | 输出副作用：隐藏重要验证失败或条件 | A | 中；省的是无关过程，不是关键限制。 |
| F14 反复无效修复 | 缺乏反馈闭环：权限错误仍重装 | B | 中；明确根据证据换方向，不写满各种故障分支。 |
| F15 普通短答会必然变长 | 过度防御：原文已有Direct和简单自检例外 | D | 不加规则；保留简单题作为回归基准。 |
| F16 不迎合导致不能安慰 | 过度防御：原文禁止空洞鼓励，并非同理心 | D | 不“修复”不存在的全面禁令；新版仅澄清两者相容。 |
| F17 直接回答与核验必然冲突 | 伪冲突：输出短不等于准备工作少 | D | 不加独立优先级专章；测试T29验证。 |
| F18 保证事实全对、永久记忆、工具成功 | 能力承诺不可能可靠实现 | C | 不新增绝对保证；提示词只控制做法和报告，依靠产品与实测。 |
| F19 自检带来虚假可信度 | 自评不独立、复杂任务无外部证据 | B | 中；保留轻量检查，不当作正确性证明。 |
| F20 “低风险”“重大”“足够”仍模糊 | 原则性规则不可避免的判断空间 | B | 接受剩余风险；具体项目可补任务级验收标准，通用prompt不枚举所有阈值。 |

不存在证据证明原作者的每条规则都来自失败体验。Activation多重禁止、反复强调不迎合、排障不罗列、执行不降级教程看起来有补偿性写法；这只是文本特征推断，不作为删除依据。

## 3. 有意保留与不采用的修复

保留中文、Windows、Java/Spring、陌生领域从基础、现代英式英语：这是有信息量的个人偏好，不能为压缩而去掉。保留原文“信息足够才推荐”和“差异小直说”，它们已经能抵抗机械选边。保留不机械追问、不无谓联网、创作交付和实际执行：都是清楚的目标。

没有增加固定回答模板、每次事实/推断/假设/未知四栏、每次两个来源、每步确认、强制角色人格、概率百分比、逐题公开自检或普遍字数上限。它们会引入新的机械成本。也没有把“准确性优先”设计成遇到任何不确定就拒绝回答；有依据的部分和条件判断仍应提供。

本版不是越短越好：真正需要的边界比单纯压缩更重要。字符数只作为维护负担的粗指标，不是token成本实测，更不是可靠性指标。

## 6. 无法仅靠Prompt解决的限制

- 实际指令遵守率和推理正确性取决于具体模型及设置。文本无冲突不等于执行稳定；本次也未证明跨模型适用性。
- 产品可能注入更高优先级的搜索、审批、格式、记忆或工具规则；本提示词不能改变它们。部署位置要记录。
- 缺失工具、权限、实时数据和被截断的历史无法靠“必须”补回来。
- 检索来源质量、引文是否真正支持结论、任务是否充分验证，仍需可审查的证据和人为抽查。
- 提示注入抵抗、隐私边界和不可逆操作不能只靠自然语言；需要工具权限及执行隔离。这里不宣称安全保证。
- 同一作者设计案例、改prompt并评分有确认偏差；定向用例不能代表真实使用分布。36+12条仅覆盖已识别风险，不能证明最优或无回归。

## 7. 最值得观察的五类真实使用

1. **一句话技术问答及高级追问**：观察是否无谓联网、逐词解释、重复用户背景；与原版盲评比较。
2. **翻译、虚构和真实宣传混合任务**：观察是否误纠正原文，或反过来借创作捏造真实事实。
3. **带偏好缺口的推荐**：记录追问是否真能改变选择，以及不问时是否擅自假设偏好；不能只追求追问次数下降。
4. **本地排障与修改后的验证**：记录无效重复修复、未验证便宣称成功、权限范围变化和实际功能结果。
5. **长对话局部改要求**：记录保留旧有效条件、局部覆盖有效期、缺失上下文时是否坦承缺口。

以实际失败样本驱动下一版：先确认失败来自prompt、模型还是工具；只有重复出现且可归因的规则问题才改通用文本。不要因一次不喜欢的措辞就新增全局禁令。
