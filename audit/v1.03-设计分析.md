# V1.03 设计分析

日期：2026-09-08。V1.02已按用户要求成为main稳定基线；“稳定”表示版本管理地位，不表示模型效果已经实证。V1.03保持通用用户偏好定位，仍是待实测候选。

## 1. 官方来源与采用范围

已实际检索、打开并阅读用户补充的[OpenAI Model Guidance](https://developers.openai.com/api/docs/guides/latest-model?utm_source=chatgpt.com)，页面当日选中GPT-6 Astra。定位为“Prompting best practices”下的同名小节；动态latest-model地址未来可能改变，不代表永久固定的模型文档。以下“官方观察”是简要转述；采用方式和边界是本项目的设计判断，不是官方通用效果结论。

| 主题/官方小节 | 官方观察或建议（简述） | 本项目抽象、采用与边界 |
|---|---|---|
| Initiative and follow-through | 可能因澄清而提前停下；利用意图及前文推进。 | 目标是完成用户当前想做的事。讨论方案的成果是判断或方案，不是文件修改；执行型请求才以实际结果为完成标准。新版§3明确四种意图，不以请求句式作机械触发器。 |
| Clarification（同节） | 先形成可审阅成果，减少非阻塞询问。 | 将询问挂在受阻步骤上，而非整项任务上；未知收件人时仍能算账、写草稿。准备工作本身必须已获授权，也不能把等待时间当许可。 |
| Conversation context（同节） | 结合先前对话推断范围。 | 当前消息确定本次变化，仍有效前文维持连续性，相关个人信息只调节回答。缺失内容不能虚构；不为个性化重复用户履历。 |
| Instruction following | 对文件指令敏感；建议明确优先级。 | 新版§1统一局部覆盖与材料边界。长期偏好不能阻塞当前明确任务；这不授予越过系统约束的权力。 |
| Personality and writing style | 易用较多格式和重复措辞；可指定段落及知识层级。 | 默认段落，列表和表格按信息关系选用。技术解释从用户已知处开始；段落偏好不覆盖指定JSON、表格、诗歌或步骤。 |
| Stock phrasing（同节） | 减少套语、术语堆砌和生造标签。 | 约束无信息修辞，不维护禁词表。正常的转折、对比和总结只要帮助理解即可使用。 |
| Directness（同节） | 直接说明实际行动。 | 少写“我会从几个方面……”等自我描述，直接给内容；重要进度、失败和限制仍需告知。 |
| Testing and verification | 编程小改动可能验证过度；按需要校准。 | 抽象为验证投入与后果、范围、不确定性和成本相称。证据满足当前目标后停止；新异常或验收未满足时继续，不照搬免测条款。 |

这些内容并不证明Astra是唯一具有上述倾向的模型，也没有官方数据证明本项目V1.03会改善它们。此处只把官方观察当作待检验的设计输入。

## 2. 明确排除的专用内容

以下为本项目选择，不进入运行正文：多代理调度比例及代理通信格式属于运行器配置；具体AGENTS.md、SKILL.md定位和逐字引用属于工具排障；worktree、PR、部署步骤属于项目流程；API模型名、推理参数、缓存及工具协议属于接口配置。它们不能改善没有这些设施的日常问答，加入会增加触发歧义。

不移植“某类可逆动作一律无需批准”，因为可逆不代表符合用户意图；不把“我想”一律解释成执行；不移植“低影响修改不写测试”的绝对形式，因为有些小修改仍有明确验收要求。保留的是目标、授权和验收之间的关系。

## 4. 新结构与行为边界

采用六节：目标与优先级；判断与证据；意图、上下文与推进；授权、完成与验证；表达与任务适配；相关个人背景。不单开“每类任务流程”章节，避免再次把核验、执行、澄清复制到每种任务下。

新增边界包括：讨论不等于实施；明确执行不止于建议；后续补充不自动取消原目标；缺口只阻塞依赖它的步骤；审批前可完成授权准备而不能提前实施；默认段落让位于任务格式；反套语不等于禁词；适度验证让位于实际验收与新异常。

同一原则有不同重要落点时不强行去重。例如§2规定诚实报告，§4规定做什么验证：前者不能替代后者。个人背景相关性也不由“利用上下文”自动保证，保留单独范围句。压缩应减少维护歧义，不追求最短文本。
