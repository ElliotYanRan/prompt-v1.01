# V1.01 静态基线（新版编写前）

完整原文来自用户指定仓库，经GitHub连接器读取，内容与本会话提供的V1.01一致。这里判断规则支持程度，不是独立模型实测。测试输入和标准见测试集.md。部分通过不等于实际回答必然失败；失败只指指定控制缺位或取舍不成立。

| ID | 评级 | 规则依据与不足 |
|---|---|---|
| T01 | 通过 | Direct明确简单稳定问题直接回答。 |
| T02 | 通过 | Direct和当前一句话要求相容。 |
| T03 | 通过 | 简答与输出限制相容。 |
| T04 | 通过 | 稳定常识例外足以覆盖；不能仅因出现软件词就判旧版失败。 |
| T05 | 通过 | Verification明确最新和查官网。 |
| T06 | 部分通过 | 要查价格，但地区、型号、口径是否一致未表达。 |
| T07 | 通过 | 版本核验方向明确。 |
| T08 | 部分通过 | 新闻时效触发与仅提取已给正文的边界不明。 |
| T09 | 通过 | 证据不足应指出；无需因此强制联网。 |
| T10 | 通过 | 明确不接受错误前提。 |
| T11 | 通过 | 能约束用户确定语气对判断的影响。 |
| T12 | 通过 | Decision明确差异小不制造区别。 |
| T13 | 通过 | 信息足够时推荐并说明成立条件。 |
| T14 | 部分通过 | 四条件同时成立才问；偏好不匹配未必算明显错误，可被不当默认值绕过。 |
| T15 | 通过 | 日志优先、低成本验证支持针对证据排查。 |
| T16 | 部分通过 | 逐步缩小有帮助，但对被证据否定的旧步骤缺乏停止条件。 |
| T17 | 通过 | 直觉、类比和用户水平明确。 |
| T18 | 部分通过 | 已有背景与“新术语第一次出现时解释”竞争；新出现不等于不熟悉。 |
| T19 | 通过 | 创作优先完成作品。 |
| T20 | 部分通过 | 翻译忠实与全局错误前提纠正之间没有明确作用域。 |
| T21 | 部分通过 | Creation保护设定，但Truth段未限定现实断言。 |
| T22 | 通过 | 虚构文案可以直接写；无需将所有创作判为问题。 |
| T23 | 通过 | 不随确定语气接受动机推断；不禁止自然回应情绪。 |
| T24 | 通过 | 原文只禁止空洞鼓励，不禁止温和支持，不能据此判失败。 |
| T25 | 通过 | 有合理默认值时继续。 |
| T26 | 部分通过 | 权限/必要信息提供一般约束，但未明确可推断文件属性不等于可推断删除意图。 |
| T27 | 通过 | 当前覆盖旧信息，结合上下文可以保留未变约束。 |
| T28 | 部分通过 | 新要求优先没有明确局部有效期，依赖模型理解“这次”。 |
| T29 | 通过 | 核验可在输出前完成，与直接回答并非真正矛盾。 |
| T30 | 通过 | 低风险默认符合Clarification。 |
| T31 | 通过 | 原文明确复杂任务可以深入，并非一律短答。 |
| T32 | 部分通过 | 不知道要说，但搜索失败/不可用时的交付状态不够明确。 |
| T33 | 部分通过 | “是否真的执行”不等于结果验证，写入成功可能被当作功能成功。 |
| T34 | 失败 | 没有区分待处理资料与有效指令；这是提示词层控制缺位，底层仍可能拦住。 |
| T35 | 部分通过 | 要实际做，但没有完整交付和验证对应关系，复杂任务容易只做一部分。 |
| T36 | 部分通过 | 当前要求覆盖旧规则可提供支持，但核验段未明确来源范围约束。 |

基线统计由表格计算，不当作胜率。优先处理T14、T18、T20/21、T33/35；T34后果较大但频率未知。不具备真实使用日志，不能宣称这些已是用户最高频实际故障。
